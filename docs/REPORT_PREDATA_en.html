      2Research question and scope

      The paper argues that managers use voluntary capital-expenditure forecasts to elicit feedback from the market: the more positive the market's reaction to a forecast, the more actual capex is revised upward relative to the forecast by year end. Tables 1–3 form the complete argument for this claim.

      The scope of this replication is Tables 1–3. The code for Tables 4–6 is also written (run with JW_SCOPE=all) but is outside this report.

      6Variable construction: formulas and code

      Notation: i is a forecast (firm-quarter), a the calendar quarter of the forecast, t the forecasted fiscal year, t₀ the event day (day 0). All variables except the dependent variable are known at or before the forecast date.

      6.1 Forecast value and type (CAPEX_FORE, FTYPE)

      range ⇔ val_2 non-missing and val_2 ≠ val_1; other ⇔ not range and range_desc in the open-ended code set; otherwise point
      L = min(val_1, val_2), H = max(val_1, val_2) (range); L = H = val_1 (point, open-ended); F = (L + H) / 2

      Amounts are first converted to $ million using units (D4). The open-ended code set is calibrated with diagnose.py once data arrive, so that the three shares approach Table 1 Panel C (D3).

      6.2 Dependent variable CAPEX_ADJ

      CAPEX_ADJi = 100 × (Ai − Hi) / Fi if Ai > Hi
      CAPEX_ADJi = 100 × (Ai − Li) / Fi if Ai < Li
      CAPEX_ADJi = 0 if Li ≤ Ai ≤ Hi

      A is Compustat capx for the forecasted fiscal year. A range forecast met inside the range counts as 0, the paper's conservative treatment; the denominator is the range midpoint (D7; alternative: the violated bound).

      6.10 Winsorising, standardising, CAR_POS and CAR_NEG

      winsor(x) = min( max(x, q0.01), q0.99 ), q = full-sample quantiles
      z(x) = (x − x̄) / s, s = sample standard deviation (N − 1)
      CAR_POS = max(CAR, 0), CAR_NEG = min(CAR, 0), each standardised (D35)

      Only ratios are winsorised (CAPEX_ADJ, CAR, CAR_PRE, SF_CAR, SURP, the scaled LAG_CAPX); dollar levels are not. The evidence is in Table 1: CAPEX_ACT and LAG_CAPX have a minimum of 0.000, while CAPEX_ADJ has a minimum of −77.05 (a point forecast followed by zero capex would give −100) (D14).       7Estimation

      7.1 The regression

      CAPEX_ADJi,a,t = α + β · CAR_zi + γ′Xi + μfirm + τa + εi,a,t

      β reads: for a market reaction one standard deviation (8.974 points) higher, actual capex is revised upward relative to the forecast by β percentage points more. Each column's X, fixed effects and clustering are in §9.

      7.2 Coefficients, standard errors and p-values

      1. Absorbing fixed effects: alternating projections demean y and each x by firm and year-quarter in turn until the change is below 1e−10.
      2. Coefficients: β̂ = (X̃′X̃)−1X̃′ỹ on the demeaned data; a constant is added when there are no fixed effects.
      3. Cluster-robust variance: V̂ = c · (X̃′X̃)−1 [Σg Sg′Sg] (X̃′X̃)−1, Sg = Σi∈g x̃iûi, c = G/(G−1) · (N−1)/(N−K).
      4. Degrees of freedom K: regressors plus the degrees of freedom of fixed effects not nested in the cluster variable (the reghdfe convention, D26). Firm fixed effects are nested in firm or industry clusters and do not enter K.
      5. p-values: t = β̂ / SE, p = 2 · Pr(tG−1 > |t|). This is why CAR_POS with t = 1.96 earns only one star in the paper.
      6. Adj. R² = 1 − (1 − R²)(N − 1)/(N − k), with k including all fixed-effect degrees of freedom; singletons are kept (D25: Table 2 reports the same N with and without firm fixed effects).

      7.3 Difference tests in Table 3

      t = (β̂Higher − β̂Lower) / √(V̂11 + V̂00 − 2V̂10), p = 2 · Pr(tG−1 > |t|)

      The paper does not say how the differences were tested. The two groups are pooled in one regression in which every regressor is multiplied by the group indicator and the firm and year-quarter fixed effects are split by group. The point estimates then equal the separate regressions, while the covariance is joint and industry-clustered, the analogue of Stata's suest.

      10Table 3: information asymmetry and the sign of the reaction, cell by cell

      AAppendix A: steps after WRDS access

      Twelve steps, each with its command, what success looks like and what to do if it fails. Details on the WRDS account, Duo two-factor login and error handling are in WRDS_GUIDE.md.

      1. Confirm the targets

        Download the published RFS article and its Internet Appendix; update paper_targets.py wherever Tables 1–3 differ from the working paper.

      2. Account and two-factor login

        Register the WRDS account and enrol in Duo; every Python connection then sends one push to approve.

      3. Pre-flight

        pip install -r requirements.txt
export WRDS_USERNAME=your_username     # Windows: setx WRDS_USERNAME "your_username"
python preflight.py

        Success: every line ok except the data line; verdict READY FOR DATA.

      4. First connection

        Run wrds.Connection() once in Python, approve the Duo push, and answer y when asked to save the password file.

      5. Access check

        python check_wrds.py                  # about 2 minutes → output/wrds_check.md

        Success: all nine tables OK and I/B/E/S has records with measure = CPX. If I/B/E/S Guidance shows NO ACCESS, stop and resolve the subscription first. Keep the table of range_desc codes from the report; step 7 uses it.

      6. Download

        python pull_wrds.py                   # 9 tables, one Duo push; log in data/raw/_pull_log.csv

        Success: no FAILED line in the log. After a dropped connection, re-run only the failed tables, e.g. python pull_wrds.py dsf.

      7. Calibrate

        python diagnose.py

        Without looking at any regression, set config.py against §14: for D3, add the range_desc codes meaning “at least / at most” to the open-ended set until the shares approach 55 / 34 / 10%; for D4, rescale unit codes with a median ratio near 1,000; confirm the 47% for D9 and the 0.559 for D10. Record each change under its ID in REPLICATION_NOTES.md.

      8. Build and estimate

        python run_all.py                     # sample, Tables 1–3, results report → output/

      9. Read the results in order

        sample_waterfall.csv → Table 1 and table1_winsor_check.csv → numbers quoted in the text → Tables 2 and 3 → replication_report.html. If the winsorisation check disagrees with D14 for a variable, update WINSOR_VARS and repeat step 8.

      10. Stata cross-check

        ssc install ftools
ssc install reghdfe
cd stata
do tables_2_3.do
* back in the package root:
python compare_stata.py               # → output/stata_crosscheck.md

        Success: all coefficients agree to rounding error and N is identical in every model.

      11. Robustness

        Switch D7, D9, D10, D14 and D18 one at a time, repeat step 8 each time, and record whether the conclusions of Tables 2 and 3 change.

      12. Report

        Explain every flagged deviation in the last section of the results report; print replication_report.html to PDF from the browser; share only the results in output/, never the raw data in data/.
